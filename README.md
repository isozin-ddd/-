# Global Viral Shorts Factory — 無限ショートメーカー

世界市場向けのオリジナル縦型動画を、端末内のCanvasで制作する静的Webアプリです。GitHub Pagesで運用し、Render・常時稼働サーバー・APIキー・ユーザーログインを必須にしません。

- アプリの既存公開先：<https://isozin-ddd.github.io/-/>
- [品質比較・サンプル](docs/samples/index.html)
- [実装と検証の状況](reports/IMPLEMENTATION_STATUS.md)
- [参考事例の調査報告](docs/references/research_report.md)

**現在の作業環境では公開URLへの接続が外向きプロキシのCONNECT 403で阻まれ、本番反映後の動作は未確認です。サイト自身が403を返したという意味ではありません。リポジトリがPublicであることは確認しています。iPhone Safari実機の録画・共有・ファイル保存は未検証です。**

## 制作機能

4ジャンル各15種類、合計60種類のテンプレートを実描画します。色や速度の変更だけでなく、経路、幾何構造、作用、時間展開が異なる仕組みを実装しています。

| ジャンル | テンプレート数 | 例 |
| --- | ---: | --- |
| Physics | 15 | Rotating Ring Escape、Bouncing Ball Maze、Gravity Funnel |
| ASMR | 15 | Jelly Compression、Glass-Like Cutting、Color Mixing |
| Surreal / Meme | 15 | Creature Transformation、Absurd Race、Impossible Object |
| Chain Reaction | 15 | Domino Spiral、Marble Machine、Gear Cascade |

Canvas 2Dのグラデーション、光沢、半透明表現、ソフトシャドウ、奥行き、パーティクル、カメラの変化で質感を改善しました。Physicsには固定時間刻みの簡易2D物理を使用します。ジェリー・液体・ガラス・機械は手続き型の視覚近似であり、実写、完全な流体計算、生成AIによる映像ではありません。

効果音は衝突・接触・切断・連鎖等の描画イベントへ同期させてWeb Audioで合成します。BGMもオリジナルの合成音です。他人の動画、楽曲、既存キャラクターは同梱しません。ループ可能な周期演出と、終了後にリセットする演出を区別して表示します。

- ジャンル／テンプレートの選択、全ジャンルからの自動選択。
- シードによる初期配置・構図・展開・結末の変更。自動一括生成では可能な範囲で異なる仕組みを選択。
- 1本、3本、5本、10本の逐次録画。**50本・100本は無効の将来機能**です。
- 9:16、360×640／540×960／720×1280／1080×1920（実験的）、3／6／10／15秒、24fps目標。
- MP4録画方式の対応判定。非対応の環境はエラーを明示し、WebMへ拡張子だけMP4を付けることはありません。
- 英語タイトル・英語ハッシュタグ案・英語字幕、字幕なしモード。
- 進捗、停止、未完了分の再試行。未完了の小さな設定データを保存し、再読み込み後に再試行可能。
- 動画ライブラリ、個別再生、MP4ダウンロード、対応環境でのファイル共有。

## iPhoneからの操作

1. HTTPSのアプリURLをSafariで開きます。Safariの実験的設定やAPIキーは不要です。
2. まず **360×640・3秒・1本**で録画し、再生・音・保存を確認します。
3. 「再生・保存」から「共有からファイルに保存」を押し、iPhoneの共有シートで「ファイルに保存」を選択します。共有非対応なら「MP4をダウンロード」を使用し、Safariのダウンロード一覧／ファイルアプリから確認します。
4. 同じ解像度・尺・音声・字幕設定で1本が完成すると、3／5／10本の生成を試せます。テンプレート変更が端末負荷へ与える影響は別途確認してください。
5. 解像度は360→540→720→1080と段階的に試します。新エンジンはデスクトップChromiumで各ジャンル代表1種類ずつの540／720／1080p・3秒録画を確認していますが、iPhone実機や高解像度10本連続では未検証です。

録画は実時間で進みます。10本×6秒には保存時間を除いても約60秒が必要です。生成中はSafariを前面に保ち、画面をロックしないでください。非表示になると録画を停止し、完成済みの動画は維持します。

## 保存とメモリ制限

- 録画・書き出し・動画保存は**1本ずつ**実行します。
- 1録画24MiB、ライブラリ30本／合計200MiB。上限や保存失敗時は処理を中断し、今回の1本を退避する保存ボタンを表示します。
- ライブラリ一覧はメタデータだけを読み、再生・共有対象の1本だけをBlob URLへ展開します。
- 管理データは各保存コレクション1MiBまで。参考資料・実績のインポートは2MiB以下、各最大2000件で、容量上限を超える場合は拒否します。
- 動画はIndexedDB、未完了設定や資料・実績のメタデータは端末内ストレージに保存します。生成動画をGitHubやSNSへ自動アップロードしません。
- Safariのデータ消去やOSの容量整理で失われることがあるため、必要なMP4と管理JSONは「ファイル」へ書き出してください。別端末への自動同期はありません。

## 参考資料ライブラリ

URL登録、ジャンル分類、いいね・再生数、特徴タグ、検証区分、数値の出典区分、テンプレートとの関連付け、いいね順ソート、ジャンル絞り込み、編集・削除、JSON入出力を実装しています。元投稿URLが不明の調査リードもnullのまま保持し、リンクや数字を作りません。

今回の調査は**44エントリー、元投稿URLがある41件、URL不明の調査リード3件**です。41URLの文字列重複はありませんが、転載映像の重複まで除外できたという意味ではありません。

**元投稿で10万いいね以上を直接確認できた事例は0件です。目標40件を達成していません。** SNSの取得制限・ログイン制限・動的カウンター等により確認できませんでした。検索結果・二次資料の歴史的数値は`reported_metrics`へ分離し、元投稿の`likes`／`views`へ転記しません。再生数やRedditのupvotesを「いいね」として集計しません。画面の達成件数も元投稿URL・元投稿での数値確認・10万いいね以上がそろう記録だけを数えます。

[調査報告](docs/references/research_report.md)、[確認方法](docs/references/source_verification.md)、`references/reference_manifest.json`と`references/reference_schema.json`に出典・確認日時・制約を記録しています。観察できなかった動画の0.5秒・1秒・3秒のフックや音の内容はnullです。制作パラメータは独自生成器を改善するための仮説であり、人気の因果関係やAIモデルの再学習ではありません。

## 投稿実績と品質評価

投稿日時、SNS、テンプレートID、再生、いいね、コメント、共有、平均視聴時間、完視聴率、フォロワー増減を手動記録できます。不明は空欄／nullのまま保存します。JSON入出力、編集・削除、テンプレート別の実測比較に対応します。

いいね率は再生数といいね数の両方がある投稿だけを合算し、母数と投稿件数を表示します。平均視聴時間・完視聴率は入力済み投稿の単純平均です。表示する改善案は比較実験の提案で、SNS間や投稿条件の違いを除いた因果効果ではありません。

品質メモは質感、滑らかさ、満足感、展開、音同期、ループ、独自性、視認性、制作原則について**人が1〜5で評価する任意項目**です。描画時間やフレーム統計による自動の目安、手動品質評価、実際のSNS実績を別々に扱います。再生数や収益を予測・保証するスコアは表示しません。

外部音源の権利台帳では出典URL、ライセンス、許諾のメモを記録できます。台帳は音源の取り込み・取得・権利の法的確認を行う機能ではありません。標準の録画音声はオリジナルの合成音です。

## 品質サンプルとテスト結果

[比較ページ](docs/samples/index.html)には先行12テンプレートのプレビュー画像と、各ジャンルの改善前／改善後、合計8本のMP4を収録しています。比較条件は360×640、3秒、同じシードで、他人の参考動画は使用していません。

**配布用サンプルは開発時にオフラインでH.264/AACへ正規化しています。** Chromiumがネイティブ録画したMP4の音声がOpusであったためです。FFmpegはアプリの依存ではなく、端末内アプリがAACを必ず出力できると検証したわけでもありません。実際の録画コーデックはブラウザが選びます。

- `reports/global-browser-results.json`：Chromium、390×844モバイル幅で1→3→5→10本、計19本のネイティブMP4録画、停止／再読込後の再試行1本を含め計20本を確認。同時MediaRecorderは1個、ダウンロードしたMP4のH.264 360×640と音声を確認。
- `reports/quality-results.json`：60テンプレートのCanvas描画、有限の音イベント、描画時間、フレーム差、ループ端点差、先行12画像、8サンプルの検証。端点の画像差は知覚的な自然ループの保証ではありません。
- `tests/management-browser-results.json`：参考資料のCRUD、JSON入出力、不正URL拒否、実績集計、再読み込み保持をChromiumで確認。
- `reports/highres-results.json`：現行エンジンの4ジャンル代表各1種類×540／720／1080幅、計12本の3秒単発録画をデスクトップChromiumで確認。H.264＋Opus音声、録画トラック終了、AudioContext終了を検証。アプリの常時プレビューを省いた録画単体の検証であり、60種類すべてや高解像度10本連続の検証ではありません。
- iPhone Safari実機、共有シート、ファイルアプリ保存、iPhoneの1080p、高解像度10本連続、長時間の発熱・メモリ安定性は**未検証**です。デスクトップの成功をiPhone実機の結果へ流用しません。

## 構成と公開

実行ファイルは`docs/`内です。`docs/catalog.js`が60テンプレートを集約し、`docs/scenes/`が描画、`docs/engine.js`が録画・合成音、`docs/storage.js`が動画保存、`docs/research-ui.js`と`docs/insights.js`が管理機能を担当します。`templates/`にテンプレートメタデータ、`references/`に調査データを保存し、Pages配信用の写しを`docs/`へ配置します。

GitHub Pagesはmainブランチの`/docs`を配信するか、`.github/workflows/pages.yml`で`docs`を公開します。`file://`でHTMLを直接開く利用方法は、ES Modulesや安全なコンテキストの制約から対象外です。公開反映と公開URLでの動作確認は別々に追跡します。

## 未実装・対象外

- 実写ASMR、真の流体計算、生成AIモデルの推論・再学習。
- SNS情報の自由な自動取得、ログイン制限の回避、動画の無断ダウンロード。
- SNSへの自動投稿、アカウント同期、収益化保証。
- 50〜100本の一括生成、バックグラウンド録画。
- 外部音源を録画へ取り込む機能、外部AI動画API。

外部AIや権利処理済み素材を追加する場合も任意機能に分離し、APIキーを公開リポジトリへ置かない構造を維持します。大量生成とSNSの収益化条件は別です。特に3〜15秒の出力は、1分超を求めるTikTok Creator Rewardsの長さ条件を満たしません。投稿前に各SNSの最新の独自性・反復コンテンツ・収益化ルールを確認してください。
